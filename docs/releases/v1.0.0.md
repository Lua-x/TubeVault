TubeVault 1.0 – ready for every day: a default port that no longer clashes with Jellyfin, an English handbook, updates tested from every earlier version, browser tests on every change, and a security review of the whole app.

### New

- **New default port 8823** ("TUBE" on a phone keypad). 8096 is Jellyfin's port, and most people run both. **Existing installs keep 8096** as long as `PORT` isn't set, so updating never makes your server unreachable; **Verwaltung → System** (admin area → system) shows the port in use and how to move over. The container's health check finds the port by itself
- **Documentation in English**: a new README and a handbook in [`docs/`](https://github.com/Lua-x/TubeVault/tree/main/docs) – installation, library, watching, living room, users and login, administration, reverse proxy, troubleshooting and privacy – plus CONTRIBUTING.md and SECURITY.md. All earlier release notes are translated too. The interface stays German; the handbook names its menus in German with a translation
- **A full disk stops the download queue** instead of letting every queued download use up its attempts and fail: the download waits without losing an attempt, the queue pauses, and a notification says why. Free some space and resume under **Downloads**
- Images also get a major-version tag: `ghcr.io/lua-x/tubevault:1` stays on 1.x

### Stability

- **Updates tested from every release**: databases written by the real code of every version from 0.1 to 0.9, and backups made by every version from 0.5 on, are part of the test suite now. Users, settings, watch progress, playlists, watch later, subscriptions, API tokens and family devices all survive, and new videos can be added afterwards
- **Browser tests** (Playwright) run on every change against a real server with demo videos: signing in, every main page, search, marking as watched, playlists, preferences, the TV view with the arrow keys and a kids profile
- Files that vanished from disk answer "not found" instead of an error, and **Dateien prüfen** (verify files) marks them missing

### Security

- Failed logins are now also limited **per account**, not only per address. Without a reverse proxy in front, a faked `X-Forwarded-For` could give every guess a new address
- Restoring a backup checks the unpacked size and the free space first, so a crafted ZIP can't fill `/config`
- A test calls every one of the 144 API routes without signing in and fails if anything outside a short, documented list answers
- CodeQL code scanning on every change; `pip-audit` and `npm audit` find no known vulnerabilities
- [SECURITY.md](https://github.com/Lua-x/TubeVault/blob/main/SECURITY.md) explains how to report a problem privately and what TubeVault protects

### Upgrade notes

- One database migration (0013) runs by itself on start; it remembers that your install used port 8096. As always, back up under **Verwaltung → Sicherung** first – going back to 0.9 isn't possible afterwards.
- **Nothing to change for the port.** To move to 8823, set `ports: ["8823:8823"]` and `PORT=8823` in your compose file; to stay on 8096 for good, set `PORT=8096`. Reverse proxies keep pointing at the port you use.
- The image's health check is now `python -m app healthcheck`. If you wrote your own `healthcheck:` in the compose file with port 8096, it keeps working as long as you stay on 8096.
- Behind a reverse proxy, consider setting `FORWARDED_ALLOW_IPS` to the proxy's address (see the [reverse proxy guide](https://github.com/Lua-x/TubeVault/blob/main/docs/reverse-proxy.md)).

```sh
docker compose pull && docker compose up -d
```
