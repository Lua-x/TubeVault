Check subscriptions on the days you choose, clear resolution names instead of "up to …", and an app that picks up updates by itself.

### New

- **Schedule for subscriptions**: besides "every 6 hours" and the like, **Auf neue Videos prüfen** (check for new videos) now offers **Nach Zeitplan** (on a schedule) – pick the weekdays and a time, e.g. Monday and Friday at 18:30. The time is the container's local time (`TZ`), summer time included. Scheduled subscriptions are checked only then: the quick RSS look doesn't move the check up. **Jetzt prüfen** (check now) still works at any time. The subscription list shows the next check, e.g. "nächste Fr., 18:30"
- **The app updates itself**: after `docker compose pull && docker compose up -d`, a TubeVault tab or installed app that is still open loads the new version the next time you come back to it – never in the middle of a video or podcast. Before, it kept running the old version until reloaded by hand

### Changed

- **Resolutions are named plainly**: "2160p (4K)", "1440p", "1080p (Full HD)" … instead of "Bis 4K", "Bis 1080p" – in the settings, in "Video hinzufügen" (add video) and per subscription, with a note that a video without that resolution comes in the next smaller one. "Standard" shows what the settings say, e.g. "Standard (Beste verfügbare)". The setting is called **Auflösung** (resolution) now instead of "Maximale Qualität"
- **"Video hinzufügen" keeps every pick right away** – format, resolution, comments – not only after a download was started
- A video's **Details** show the exact resolution, e.g. "4K · 3840 × 2160", and 8K videos as 8K instead of 4K

### Upgrade notes

- One database migration (0015) runs by itself on start. As always, back up under **Verwaltung → Sicherung** first – going back to 1.0.x isn't possible afterwards.
- Set `TZ` in your compose file (e.g. `TZ=Europe/Berlin`) so schedules use your time; without it they run in UTC.

```sh
docker compose pull && docker compose up -d
```
